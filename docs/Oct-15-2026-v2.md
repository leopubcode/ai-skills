## Herdr

It is a lot simpler to manage multiple agents with herdr so install it with brew:

```bash
brew install herdr
```

### sbx plugin

Now since we are using sbx we need this plugin: https://github.com/dirien/herdr-sbx-plugin

It is not a very popular plugin so I asked claude to do a security review and it reported it looks safe, but to be aware of new updates. There is no internet access and no dependencies so the code you see is what you get. Follow the readme for up to date instructions. There are configurations you can add to customize behavior. The one I find important is to open agents in a new tab instead of a new pane. Things like CPU and memory are also important though. Follow instructions for how to add a config file https://github.com/dirien/herdr-sbx-plugin#configuration.

```bash
{
  "openIn": "tab",
  "workspaceMode": "clone"
}
```

You will now see the sbx agents in herdr but only if opened via this plugin. Which you can do by running the `start-agent` action from this plugin which is `herdr plugin action invoke start-agent --plugin sbx.sandbox`. Since this is too long you should instead add an alias for it in your `~/.zshrc`:

```bash
alias sbx-start="herdr plugin action invoke start-agent --plugin sbx.sandbox"
```

This will allow you to start an aggent programatically. You can then run `herdr` if you want to attack to the session.

### herdr CLI

The nice thing about herdr is that it offers a CLI to manage everything so you can programatically start agents like claude in sbx programatically like in response to webhooks or custom scripts like this:

```bash
# get an existing pane, though you need to logic to know which one to pick
herdr pane list | jq .
# or create a new tab (or pane) and get the ID, you might need more logic to select the workspace first
# this works for a single workspace or the current focused workspace
PANE_ID=$(herdr tab create | jq .result.root_pane.pane_id)

# you can also add some setup script that persist the workspace ID and focus in before creating a tab
# though you need to add custom logic to know which ID you persist
WORKSPACE_ID=$(herdr workspace list | jq '.result.workspaces[].workspace_id')
herdr workspace focus $WORKSPACE_ID

# start sbx claude in a pane
herdr pane send-text $PANE_ID "sbx run claude" && herdr pane send-keys $PANE_ID enter
# or in a single command
herdr pane run $PANE_ID "sbx run claude"
```

Now with the sbx plugin there is no need to manually do any of the commands above to start an agent, but you can still use the `prompt` command to programatically communicate with the agent after it has been started.

```bash
# get the pane ID, you can persist it to reference it programatically later
PANE_ID=$(sbx-start | jq .result.context.focused_pane_id)

# get the current output
herdr agent read $PANE_ID

# prompt it
herdr agent prompt $PANE_ID "what is your current working directory?"

# get agent details
herdr agent get $PANE_ID | jq .
```

With all these tools you can easily integrate agentic workflows programatically without relying on vendor specific mechanisms. For instance getting an agent status allows you to determine if there is any new activity by tracking the value of `state_change_seq` if it changed since the last time you checked then there is new activity. There is the `agent_status` that let's you figure out the overall status.


## Scoped GitHub access

Create an [PAT in GitHub](https://github.com/settings/personal-access-tokens) with access to a single repo and with only the following permissions:

- Metadata: Read
- Actions: Read-Write
- Issues: Read-Write
- Pull Requests: Read-Write
- Contents: Read-Write

You can then run on branch mode which is firther isolation for parallel agents

```bash
sbx run claude . --branch my-branch

# to get a list of sandboxes by name
sbx list

# (recommended) give restricted access scope to a PAT
sbx secret set github --sandbox [SAND_BOX_NAME] # it will ask you to enter the token

# (not recommended) give full access with your default token
sbx secret set github --sandbox [SAND_BOX_NAME] -t "$(gh auth token)"
```

If you want to programatically add secrets to a sandbox you will run into the problem of how to reference each sandbox since they are all named in a cryptic way. Fortunately, you can get cross reference it with this script right when you start the sandbox since the result contains a part of the hash of the sandbox which is used in the tag label. This works as of versions `herdr 0.9.5` and `sbx.sandbox 0.1.0 sha256:369c420ed49a918513766dd2d804560bcc023948`.

```bash
OUTPUT=$(sbx-start)
SANDBOX_TAG_LABEL=$(echo $OUTPUT | jq .result.context.tab_label)
echo $SANDBOX_TAG_LABEL; # sbx claude-code 5d563a

last_word="${SANDBOX_TAG_LABEL##* }" 
echo $last_word; # 5d563a

SANDBOX_NAME=$(sbx list --json | jq -r '.sandboxes[].name' | grep $last_word)
sbx secret set github --sandbox $SAND_BOX_NAME -t $MY_SECRET
```

## Speech to text

VoxType offers one of the best products out there, but it is a bit buggy in macOS. I hope in a few weeks or months it will be fixed. However, even that way it offers better UX than OpenWhishper. Follow this guide https://github.com/peteonrails/voxtype/blob/dev/docs/INSTALL_MACOS.md.

__ONLY GRANT MICROPHONE PERMISSION TO TERMINAL. DO NOT GRANT IT FULL ACCESSIBILITY PERMISSIONS SO IT DOESN'T GET FULL KEYBOARD STROKES SINCE I DON'T TRUST IT THAT MUCH.__

The problem is that I was unable to launch it as a daemon. It simply doesn't work and keeps asking for microphone access time and time again. I tried downloading the mac app and the same thing. What works is to simply run it as a daemon

```bash
brew tap peteonrails/voxtype
brew install --cask peteonrails/voxtype/voxtype

voxtype daemon
voxtype setup --download --model base.en
voxtype configure # enable notifications, disable OSD, output mode = clipboard, disable hotkey evdev listener, model whisper base.en
```

With this setup you need to launch the command yourself with:

```sh
voxtype record start
voxtype record stop
# or call this twice on start and end
voxtype record toggle
```

It is annoying to toggle it this way so in macOS you can setup a shortcut that runs `voxtype record toggle` and add a keyboard shortcut with `ctrl+r` within the native `Shortcuts.app`. This is so much faster than any other app like Openwhispr which has a delay of a few seconds on text voxtype is instantaneous. Hopefully they fix the bugs so that you can simply run it as an app or as a service in the background without the microphone bug.

### Agentic engineering

With this foundation you can personalize your workflow to create custom systems to connect your agents with all sorts of data sources like Databases, Sentry, GitHub Pull requests, GitHub CI/CD, Project Management tools, etc. You can also connect to remote agents in remote machines, cloud providers, and even in k8s clusters.

Yes, there are platforms dedicated to that, but in this day and age of cheap software you can easily create something custom for your needs without much of a hazzle and remain in control of your workflow without getting vendor-locked-in while the industry figures out the best way to do it. In some cases you can write adapters for some of those platforms or services so that you can integrate with them in a decoupled way and continue to support a vendor agnostic agentic workflow.
