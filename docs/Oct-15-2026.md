## Herdr

It is a lot simpler to manage multiple agents with herdr so install it with brew:

```bash
brew install herdr
```

### sbx plugin

Now since we are using sbx we need this plugin: https://github.com/dvdksn/sbx-herdr

It is not a very popular plugin so I asked claude to do a security review of commit `9760e11` and it reported it looks safe, but to be aware of new updates. There is no internet access and no dependencies so the code you see is what you get. It simply communicates with the docker daemon and the herdr server which is reasonable. Although it can see session data, but since there is no internet access or dependencies then I'm not concerned. So simply build it from source since it is not a popular package and run the commit above or review the latest commit.

```bash
git clone https://github.com/dvdksn/sbx-herdr ~/dev/sbx-herdr
cd ~/dev/sbx-herdr
git checkout 9760e11

brew install go # if you don't have it already

make build 
herdr plugin link ~/dev/sbx-herdr 
herdr plugin action invoke dvdksn.sbx-herdr.refresh
```

You will now see the sbx agents in herdr.

### (New way) Start an agent with CLI

You can start an agent instead of issuing the raw commands to start it, so far this does not support sbx. You still need to get the pane ID in some other way like the in old guide:

```bash
herdr agent start $AGENT_NAME --kind claude --pane $PANE_ID
```

#### (Old way) Manually starting an agent with raw commands

```bash
# get an existing pane, though you need to logic to know which one to pick
herdr pane list | jq .
# or create a new tab (or pane) and get the ID, you might need more logic to select the workspace first
# this works for a single workspace or the current focused workspace
PANE_ID=$(herdr tab create | jq .result.root_pane.pane_id)

# you can also add some setup script that persist the workspace ID and focus in before creating a tab
# though you need to add custom logic to know which ID you persist
WORKSPACE_ID=$(herdr workspace list | jq '.result.workspaces[].workspace_id')
herdr workspace focus $WORKSPACE_ID

# start sbx claude in a pane
herdr pane send-text $PANE_ID "sbx run claude" && herdr pane send-keys $PANE_ID enter
# or in a single command
herdr pane run $PANE_ID "sbx run claude"
```

## Scoped GitHub access

Create an [PAT in GitHub](https://github.com/settings/personal-access-tokens) with access to a single repo and with only the following permissions:

- Metadata: Read
- Actions: Read-Write
- Issues: Read-Write
- Pull Requests: Read-Write
- Contents: Read-Write

You can then run on branch mode which is firther isolation for parallel agents

```bash
sbx run claude . --branch my-branch

# (recommended) give restricted access scope to a PAT
sbx secret set github --sandbox [SAND_BOX_NAME] # it will ask you to enter the token

# (not recommended) give full access with your default token
sbx secret set github --sandbox [SAND_BOX_NAME] -t "$(gh auth token)"

```
